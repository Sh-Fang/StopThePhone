# 范围

- 只做安卓，原生 Kotlin + Jetpack Compose，minSdk 29（Android 10），targetSdk / compileSdk 36。
- 自用侧载，不上架，不考虑应用商店对无障碍权限的审核。目标手机是小米 14（Android 16 / HyperOS 3.0）。
- 数据全部存本地，不联网。

# 功能

## 管控配置

- 从已安装应用里勾选管控应用。候选列表只列有桌面图标、且不带 `ApplicationInfo.FLAG_SYSTEM` 的应用，排除本应用。
- 每个管控应用配置多段管控时段，每段包含开始时刻、结束时刻、生效的星期几。
- 结束时刻早于或等于开始时刻视为跨午夜，算在开始那天的星期里。例：周五勾选、22:00–07:00，覆盖周五 22:00 到周六 07:00。
- 一个应用的全部时段可以复制到其他管控应用，复制时覆盖目标应用原有时段。
- 默认放行时长存在设置里，初始 15 分钟。

## 拦截

- 管控应用到前台时，如果它正处于管控时段、且没有生效中的放行，就盖上拦截页，同时生成一条拦截事件。
- 管控应用已在前台时，遇到管控时段开始、或放行到期，立刻盖上拦截页。
- 拦截页内容：应用名、当前时段结束时刻、理由输入框、放行时长（默认值，可改）、「放行」按钮、「离开」按钮。
- 「放行」按钮在使用理由有效之前不可点。有效的标准：去掉空白字符和标点（Unicode 类别 P、S 和空白）后，剩余字符数不少于 10。
- 点「放行」：生成放行和理由记录，拦截事件结局记为放行，撤掉拦截页。
- 点「离开」、按返回键、按 Home 键或切到别的应用：拦截事件结局记为放弃，撤掉拦截页，回到桌面。

## 放行

- 一次放行只对一个管控应用生效。
- 放行按真实时间倒计时，结束时刻取「提交时刻 + 放行时长」和「当前管控时段结束时刻」中较早的那个。
- 放行期间切出去再回来，不重新拦截。

## 设置保护

- 某个管控应用正处于管控时段时，对它做放宽限制的修改（取消勾选、删除或缩短时段、取消星期）需要先填使用理由，理由记录的用途记为「修改设置」。
- 加严限制的修改（新增管控应用、新增或延长时段）不需要填理由。
- 从系统设置里关闭无障碍或卸载本应用，无法阻止。

## 统计

- 时间维度：日、周、月切换，展示拦截次数、放弃次数、放行次数、放行总时长、使用时长的趋势。
- 应用维度：按拦截次数、放行次数、使用时长给管控应用排行。
- 小时维度：一周 × 24 小时热力图，格子的值是拦截次数。
- 结局维度：放弃与放行的占比。
- 理由回看：按应用、日期范围筛选理由记录。
- 图表全部用 Compose Canvas 自己画，不引第三方图表库。

## 导出与导入

- 通过系统文件选择器导出为一个 JSON 文件，包含全部配置和记录。
- 导入时先清空本地数据，再整体写入。

# 架构

## 模块与分层

单模块 `app`，按包分层：

- `data`：Room 数据库、DAO、DataStore 设置、导出导入。
- `domain`：管控时段计算、使用理由校验、统计聚合，纯 Kotlin，不依赖安卓类，方便单元测试。
- `guard`：无障碍服务、拦截页窗口、到点计时。
- `usage`：使用时长同步。
- `ui`：Compose 页面（首页、应用详情、选择应用、统计、理由回看、设置与权限引导）。

## 前台应用检测

- 用无障碍服务监听 `TYPE_WINDOW_STATE_CHANGED`，从事件的包名得到当前前台应用。
- 输入法、系统界面（`com.android.systemui`）和本应用自身的事件不改变前台应用的判断。

## 拦截页窗口

- 由无障碍服务通过 `WindowManager` 添加 `TYPE_ACCESSIBILITY_OVERLAY` 类型的全屏窗口，内容是 `ComposeView`。这种窗口不需要额外申请悬浮窗权限。
- 窗口要能获取焦点，才能弹出输入法。返回键在根视图的 `dispatchKeyEvent` 里截获。
- 「离开」按钮调用 `performGlobalAction(GLOBAL_ACTION_HOME)`。
- 窗口挂上 Compose 需要自己提供 `LifecycleOwner` 和 `SavedStateRegistryOwner`（`OverlayLifecycleOwner`）。
- 2026-11-16 在小米 14（Android 16 / HyperOS 3.0）上验证通过：拦截页能盖住抖音，搜狗输入法正常弹出、能输入，`imePadding` 让页面随键盘上移；输入法弹出时第一次返回键先收起键盘，之后的返回键被拦截页截住；「离开」能回到桌面。
- 按 Home 键时，拦截页不会自己消失，会留在桌面上，所以必须由服务检测到前台已经不是管控应用，再主动撤掉。在 HyperOS 上，按 Home 后第一条事件的包名不固定，实测出现过 `com.android.quicksearchbox`、`com.miui.personalassistant`、`com.miui.home`，所以判断条件是"前台变成了别的应用"，不是"前台变成了桌面"。
- 忽略三类事件，它们不代表前台应用切换：本应用自身（拦截页弹出时会产生）、`com.android.systemui`、已启用的输入法（点输入框时会产生）。
- 已实测通过的场景：键盘开着按 Home、没开键盘按 Home、切到微信、打开最近任务，拦截页都会撤掉；再回到抖音，拦截页重新盖上。

## 到点计时

- 无障碍服务常驻，用协程计算「下一个需要重新判断的时刻」（最近的时段开始、时段结束、放行到期），到点后重新判断当前前台应用。
- 配置或放行发生变化时，重新计算这个时刻。
- 不用 AlarmManager，服务被杀后计时也就没有意义了。

## 保活

- 无障碍服务启动后调用 `startForeground`，挂一条常驻通知，提高进程优先级。
- 设置页提供权限引导：无障碍、使用情况访问、通知、忽略电池优化、小米的自启动设置。
- 侧载安装要在开发者选项里打开「USB 安装」；用 adb 写 `enabled_accessibility_services` 开启无障碍服务，需要打开「USB 调试（安全设置）」。
- 开机后，系统会自动重新绑定已开启的无障碍服务，不需要监听开机广播。

## 使用时长

- 系统的使用情况事件（`UsageStatsManager.queryEvents`）只保留几天，所以用 WorkManager 每 6 小时增量同步一次，按 `ACTIVITY_RESUMED` / `ACTIVITY_PAUSED` 配对成前台片段，存进 Room。
- 记录上次同步到的时间点，下次从这个时间点继续。
- 统计时，把片段按管控时段切分，分别计入时段内和时段外。

# 数据模型

所有时间戳都是毫秒级 epoch，时刻用「当天第几分钟」表示。

- `controlled_app`：`packageName`（主键）、`label`、`createdAt`
- `control_period`：`id`、`packageName`、`startMinute`、`endMinute`、`daysMask`（第 0 位是周一，第 6 位是周日）
- `release`：`id`、`packageName`、`reason`、`purpose`（`RELEASE` 放行 / `MODIFY_SETTINGS` 修改设置）、`createdAt`、`durationMinutes`、`endAt`。`purpose=MODIFY_SETTINGS` 时 `durationMinutes`、`endAt` 为空
- `intercept_event`：`id`、`packageName`、`shownAt`、`closedAt`、`outcome`（`RELEASED` / `GAVE_UP`，未结束时为空）、`releaseId`
- `usage_session`：`id`、`packageName`、`startAt`、`endAt`
- DataStore：`defaultReleaseMinutes`、`usageSyncedUntil`

# 权限

- `BIND_ACCESSIBILITY_SERVICE`（服务声明）
- `PACKAGE_USAGE_STATS`（使用情况访问，需用户在系统设置里手动打开）
- `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、`POST_NOTIFICATIONS`
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
- 查询已安装应用：在 manifest 的 `<queries>` 里声明 `MAIN` + `LAUNCHER` 的 intent

# 开发顺序

- 管控配置与时段计算（含单元测试）。
- 无障碍服务、拦截页、放行、到点计时。
- 使用时长同步。
- 统计页。
- 导出导入、权限与保活引导。
